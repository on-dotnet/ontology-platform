# 快速上手

从仓库根目录操作。先启动开发栈，再用钢铁案例分两条路线体验：资料识别、审核与发布；数据查询与问答。资料识别与问答需要可用的模型服务；模型调用和镜像构建所需时间取决于本机环境。

## 准备

- 安装 Docker（含 Compose），让 PowerShell 7 能调用 Docker，并取得本仓库代码。
- 准备一个可用的 Docker 上下文。`dev.ps1` 默认连接项目的远端 Docker 主机；在自己的机器上运行时，必须改为自己可用的上下文和主机地址。目前只在一台远端 Linux 主机的 rootless Docker 上验证过，其他环境可能需要自行调整。
- 模型 API Key 可选。没有 Key，开发栈仍可启动，资料也能上传；AI 识别会失败，无法完成下文的资料识别、AI 绑定建议和自然语言问答。仍可导入案例本体、人工审核和绑定，并浏览已发布的数据。

## 配置

运行 `./dev.ps1 init-env`，在仓库根目录生成被 Git 忽略的 `.env.local`；也可以在调用脚本的环境中设置同名变量。环境变量优先于该文件。不要提交 Key 或其他凭据。

在自己的机器上，至少设置 `OP_DOCKER_CONTEXT`（现有的本机 Docker 上下文名称）和 `OP_DEV_HOST`（浏览器能访问的 Docker 主机地址）。脚本内置的默认值指向项目开发主机，不适用于一般本机安装。需要换端口时设置 `OP_WEB_PORT`；默认是 `28080`。构建镜像时依赖默认从国内镜像源下载，在国内以外的网络里设置 `OP_MIRROR=off` 改用官方源。`.env.example` 末尾的“开发栈”一段有这几项的示例；完整说明见 `dev.ps1` 和[开发手册](development.md#环境)。

要体验 AI，再在本机配置文件或环境变量中提供 `OP_OPENAI_API_KEY`。所用模型可由 `OP_AI_MODEL`、`OP_AI_REASONING_MODEL` 指定；如 Docker 主机需要代理或兼容服务，按[模型配置说明](development.md#大模型)设置 `OP_AI_PROXY` 或 `OP_AI_BASE_URL`。模型 Key 只经环境变量或不入库的文件提供。可用 `./dev.ps1 ai-check` 检查模型连接。

## 启动

```powershell
./dev.ps1 init-env
./dev.ps1 up
./dev.ps1 status
```

`up` 构建并启动开发栈，等待服务健康后显示访问地址。浏览器打开 `http://<OP_DEV_HOST>:<OP_WEB_PORT>`；未改端口时为 `28080`。开发账号见[开发手册的“开发账号”一节](development.md#开发账号)，仅用于开发环境。

## 体验一遍

下面的界面名称以中文界面为准。有两条互相独立的路线：路线一看 AI 怎样从资料里识别本体，路线二用一份现成的演示本体走数据绑定、查询和问答。两条路线各建一个本体，不要混在同一个本体里。每次合并改变的是工作版本；查询使用已发布版本。

### 路线一：从资料识别本体（需要模型 Key）

1. **上传资料。** 登录后在“本体”页点“新建本体”，创建方式选“空白本体”并起名。在这个本体的“资料”页点“上传资料”，选择 `samples/steel/docs/` 下的 Markdown 资料。资料页会显示处理步骤；完成后点“查看变更集”，查看建议及其“资料原文”。
2. **审核并发布。** 到“审核”页逐项接受、修改或拒绝建议，全部决定后点“合并到本体”。到“版本”页点“发布新版本”，填写“版本标题”并点“发布版本”；版本列表会出现新版本。

识别结果取决于模型，每次可能不同，这条路线到发布为止。下文的记录数和问答结果只适用于路线二。

### 路线二：演示数据查询与问答

这条路线按[演示脚本](specs/007-m4-qa-metrics-rules.md#132-演示脚本)的第 0 步和 Q1 准备。没有模型 Key 时可以做第 1–4 步，绑定改为手工完成。

1. **导入演示本体。** 在“本体”页点“新建本体”，创建方式选“从 OWL 文件导入”，名称填“钢铁质量演示”，选择 `samples/steel/qa/ontology.ttl` 并点“导入文件”。导入会生成一个待审核的变更集；到“审核”页确认其中的质量检验类型和约束，接受后合并。
2. **装入样例数据。** 在仓库根目录运行 `./dev.ps1 seed-steel`。它把合成数据装入开发用 PostgreSQL 的 `steel_mes` 库，建立只读账号；不要在生产环境运行。
3. **建立数据源并绑定。** 在“数据”页点“新建数据源”。主机、端口、库、用户名和开发口令从[冶金样例库说明](development.md#冶金样例库-devps1-seed-steel)查取；“模式范围”选 `mes`。保存后点“测试连接”和“读取目录”。然后任选一种方式绑定：
   - 手工：在“本体”页打开对象类型，点“绑定数据”，选择表、主键、属性列和关系；
   - AI（需要模型 Key）：在“数据”页数据源的目录里，或在“本体”页对象类型的绑定一栏点“AI 建议绑定”，选好范围后生成变更集。可对照 `samples/steel/qa/expected-bindings.toml` 核对建议。

   绑定生成的变更集到“审核”页合并，再到“版本”页发布新版本。
4. **浏览对象与关系。** 在“探索”页打开“对象”，选“质量检验”查看记录；点一条记录，在详情中的“关系”继续浏览，并查看“来源”。按 `expected-bindings.toml` 绑定完整时，演示脚本的预期是 43 条质量检验记录。
5. **提问（需要模型 Key）。** 要看到文字回答，先在“数据”页编辑数据源，打开“允许把样本值发给模型”（作用见下段）。在“探索”页打开“问答”，输入“Q235B 一共有哪些炉次？”并点“提问”。演示脚本的预期是 18 个炉次；点“查看依据”核对本体元素、数据绑定和查询步骤（导入的本体没有资料出处）。真实模型的回答效果仍需单独评测。

数据源的“允许把样本值发给模型”默认关闭。打开后有两处作用：AI 建议绑定时，每列最多 5 个取值会发给模型服务，并作为证据显示在审核页，所有登录用户都能看到；问答时，回答涉及的结果行（最多 50 行）会发给模型生成文字说明。关闭时，问答仍给出事实和依据，只是没有文字说明。

若要继续体验指标、规则、问答缺口和能力问题，按[开发手册的 M4 演示](development.md#m4-演示)完成后续步骤。

## 常见问题

- **地址打不开？** 用 `./dev.ps1 status` 查看容器状态和访问地址。确认 `OP_DOCKER_CONTEXT`、`OP_DEV_HOST` 与 `OP_WEB_PORT` 指向自己的环境；开发栈只发布 web 端口。
- **资料处理失败？** 没有模型 Key 时会报 `ai.not_configured`。配置模型后，在“资料”页重试；可用 `./dev.ps1 logs api` 查看最近日志。
- **另一个工作区也在运行？** 开发栈只有一套，同一时间只让一个工作区运行 `./dev.ps1 up`。
