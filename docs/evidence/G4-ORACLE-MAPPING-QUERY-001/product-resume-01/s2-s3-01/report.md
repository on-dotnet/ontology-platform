同一窗口的放行条件为 **Oracle 卷新增＋容器层新增＋宿主新增＋四个替代平台卷超过既有余量的部分 ≤ 69,533,250 B**，并保持其余冻结分项。现有证据不足以给出这四项的联合上界。

旧七角色窗口内，同一 Oracle 卷增长 203,277,824 B，可写层同时增长 1,015,808 B，平台卷增长 16,384 B，落在上述平台预留内。当时宿主下降，旧窗口总账净减 33,044,992 B。本轮不会预先计入那次宿主下降。若两项正向计费的增长重现，其余不变，将新增 **204,293,632 B**，较收尾余额缺 **134,760,382 B**。仅重现单卷增长时缺 133,744,574 B。这两个数都是历史情景差额。完整十槽未来的峰值和精确缺口仍未知。

**最小处置项**是授权在原 40 GiB 内，为本任务可替换副本建立可执行、可验收的写入额度。它需覆盖整个 Oracle 数据卷，并给容器层、宿主证据及平台卷溢出留出可验证的余量。按此次测量，即使后面三项均为零，替代卷总量也最多容纳到 **5,215,529,609 B**；实际准入值还须扣除这三项并在开窗前重测。若方案需要暂存或迁移，其峰值也在同一账本核验。现行公式下，单靠释放宿主文件的最高有效余额为 138,686,018 B，距上述并发情景仍差 65,607,614 B。本轮授权限于只读核查，未调整存储或额度。
