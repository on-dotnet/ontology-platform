## 三个根因

1. 现行V3按docs/evidence/<TaskId>/前缀纳入全部非PNG，缺少同一任务内部历史Run与最终证据的选择机制。保留失败原件是必要要求，但不等于每轮全部原文必须随最终ZIP交付。
2. Base→H完整文本diff再次纳入新增证据全文。成员SHA去重不能消除patch内部带加号的重复内容。只减少附件也不足以压到15MiB，证据diff本身已超过上限。
3. 记录层级重复嵌入同一事实。Run34的2477条exec_exited在入口journal、ingress-m1-closed.json及gate-I08.json重复出现。Run06/raw-output.json原文53167912字节，压缩2671330字节。这些细粒度材料有恢复/诊断价值，但无需多层重复作为主要审查材料。

Master此前先申请64MiB，跳过了应先完成的减量结构分析。保留原始失败与把全部原文纳入最终ZIP应明确区分，不能把全部体积都归为产品验收的必要成本。

## 尚未批准的减量方向

建议先核验减量方案，再决定是否还需容量例外：

- 包内保留完整现行源码、源码/测试/配置/合同差异、最终Run验收、独立Review、必要审批及关键失败→修复链。
- 历史Run原件保持Git原始blob和本地原件，完整列出commit/blob/SHA/size/path与恢复方法。选择规则不能掩盖失败或绑定变化。
- 证据文本差异采用完整变更索引及两侧blob恢复；代码/合同/配置完整diff仍保留。此项必须明确修订V3创建与VerifyOnly共同合同，不能静默省略。
- 新增摘要引用原始日志散列与位置，避免再次内嵌长事件数组；不重写旧证据。
