# 02 · G4 AI Native 数据连接、语义映射与受控查询 PRD V1.1

> 本章是 ChatGPT 本次提出的完整产品合同，不代表这些页面/API 已落地。范围：五源连接器；正式实例查询保持源端只读。目标：无需用户手工编写 SQL/SPARQL 或繁琐配置即可把生产系统数据安全纳入本体驱动的查询与 Agent。

## 1. 用户场景与结果定义

核心场景：质量分析员想知道“一炉 Q235B 出钢温度及 LF/RH 进站温度为何异常”，现有 QMS/MES 中的炉次事件在 Oracle/PG，工艺历史在 TDengine，汇总分析在 Doris，外部设备服务可能提供 Web API。用户应在已批准范围内提出自然语言问题，平台自动沿已发布本体选择合法数据路径，返回证据完整且能解释的结构化数据。**G4 只交付可信连接、映射和受控数据访问，不承诺在本关生成完整根因结论（G7）。**

业务成功标准：
1. 管理员首次配置一类数据源，页面只要求服务端无法推断的最少必填项；有效密码/Secret 在保存后不显示，测试前可以改；测试结果有分阶段错误和安全提示。
2. 平台发现允许访问的 schema/数据集并推荐语义绑定；业务专家只需要确认有歧义、有风险或缺乏证据的映射，不逐列手工配置。
3. 审核人批准某一个固定的 MappingVersion，发布后用户在一个语义界面提问；不需知道源表名、JOIN 细节、厂区编码和接口 URL。
4. 发生源超时、无权限、数据缺失、跨厂同号、schema 变化或部分子源不可用时，系统明确给出可重试/可修正的下一动作，不伪造结果、不自动放宽访问。
5. 每次查询均能从页面追溯到 `SourceId/MappingVersion/SchemaFingerprint/SourceRecordRef/validTime/observedAt/Trace`；敏感标识按权限脱敏。

## 2. Personas / 使用权限（复用现有真实角色；新增细粒度能力须经另行 ADR）
| 人员 | 主要任务 | 权限提案 / 防越权 |
|---|---|---|
| 平台数据管理员 | 新建/编辑连接、测试、停用、Secret轮换、可见 schema 范围 | `connection.manage`（待登记），不得自动成为业务数据查看者 |
| 数据建模者/领域专家 | 语义绑定、术语/单位/身份规则复核、影响分析 | `mapping.edit`（待登记），不能绕过发布审批或访问跨Scope数据 |
| 审核发布者 | 查看映射Diff及风险、异人审批、激活/回滚 | `mapping.approve/activate`（待登记），主体分离；同人双角色不得自批 |
| 质量分析用户 | 自然语言探索/实体查询/时间追溯/证据导出 | `semantic.read`+源业务授权交集，不可见凭据和未经发布映射 |
| 安全/运维 | 查看运行状态、错误码、审计/Trace/恢复 | 不自动获得源数据读取或凭据解密权限 |

新增 Policy、Role、action 不得视为 G2 已实现。用户已有 Keycloak 身份和站点隔离，G4 细粒度权限仍需显式 ADR+测试。

## 3. 信息架构（不创建 5 个互相割裂的后台系统）
导航属于现有“数据与映射”分组，建议 4 个主页面 + 若干详情页/抽屉：
- `数据源`：所有连接列表；按类型/组织厂区/状态过滤；新建向导/详情/测试/版本/禁用/Secret轮换。
- `数据模型`：Schema 库/表/API operation 与字段列表、元数据版本、变化提示、语义推荐；不展示无权 schema。
- `语义映射`：候选工作台、自动推荐、批量复核、Diff/影响、审批发布、历史/回滚；以本体 Class/Property 引导，不要求业务员输入 IRI。
- `语义数据探索`：中文问句、推荐实体/关系和查询条件，执行计划预览、结果状态、证据/水位、手动纠错和反馈；不提供任意 SQL 编辑器。
- `运行与诊断` 使用现有治理/运维分组的过滤入口，汇聚连接、Schema、Mapping、Query 的 Trace；不独立加一个大而全一级菜单。

前端 Next16/React19/shadcn/ui/Tailwind4/Base UI，配合既定 TanStack Query、React Hook Form+Zod、Zustand 与 Cytoscape.js，保持 Tailwindadmin 彩色企业管理台。状态驱动按钮与文案，移动端可只读诊断；关键图谱和映射优先桌面。所有用户操作有可观察反馈，不在界面显示给 Codex 的任务口令、工程门禁、技术说明。

## 4. AI Native 关键原则
- **第一体验是向导而不是 SQL 表单**：选择数据源类型→自动填默认 TLS 选项和推荐配置→输入必要信息→一键测试；可以记住上次安全输入，不预填敏感 Secret。
- **Schema 先于样本数据**：优先使用 `information_schema`/官方 metadata 与 API schema；**默认不读取真实业务样本，更不把样本自动传第三方模型**。AI 对元数据推荐业务类型、单位、外键、身份组合时必须携带依据；无法确定则请用户决定。
- **AI 把可自动确定的事情做完**：识别工序、同义词、常见温度字段（仅候选）、建议 Join 键与时间口径、产生映射 diff/预览、提出风险摘要；**只作为提案，不直接发布**。
- **语义模型是正式语境**：AI 仅读取授权可见的 G3 OntologyRelease、SKOS、IdentityClaim 和已登记能力；不能从自然语言修改 G3 本体，也不能将推断关系冒充已验证源事实。
- **模板化动作、用户做最终决策**：低风险匹配可批量预选，人只审冲突/未知和发布影响；关键安全/身份/单位跨尺度映射必须人审，不以模型自报分数取代验证。
- **可用性不能以模型为前提**：没有 LLM Key，仍应可新建连接、发现 schema、手工确认和执行已发布查询；AI 不可用时可降级为确定性规则+人工表单，不能阻断正式读取。

## 5. 六段旅程（每一旅程有成功、失败及恢复）

### J1 新数据源首次接入（管理员）
入口 `数据源→新增`；选 PG、Oracle、Doris、TDengine、Web API 中一种。类型决定动态表单及默认值，保存前实时字段校验；凭据走安全 SecretRef。点击“测试连接”返回网络、TLS、身份、可见对象、只读角色能力五段探测结果与诊断；没有 permission 的字段显示 `NOT_VERIFIED` 而非无意义 PASS。管理员可 `保存草稿→重新测试→启用`；保存成功后返回列表且状态正确；支持断网/超时继续编辑，密码永不回显。**不允许先添加一个“来源系统名”就称已接入。**

### J2 Schema 发现与变更处理（管理员→专家）
在连接详情 `发现数据模型`，系统只列当前允许 schema、表/视图及 API operation，展示最后扫描时间、数量、权限、错误与 schema hash。选择对象→查看列名/类型/nullable/keys/时间→建议对齐领域术语。定期或手动重新发现，计算 `SchemaFingerprint` Diff；若删字段、改类型/单位、变更 endpoint 输出，应把依赖 Mapping 标为 `REVALIDATION_REQUIRED`，维持已发布版本的可审计引用，查询遇破坏字段必须 `PARTIAL/UNAVAILABLE`，不得猜列名续跑。

### J3 AI 引导的语义映射（领域专家）
用户选择已发布本体和数据对象，系统自动生成：候选实体类型、属性、关系、IdentityKey、单位/时间与转换规则、样本对账建议、来源依据、风险分级。右侧问题队列按 `自动可确定/需审阅/阻断` 分组，专家批量确认可核实项，只对冲突或不支持的转换逐一裁决；若找不到合适 Class，生成 G3 本体扩展建议（独立审批流程），允许“暂缓/不映射”，绝不直接新建正式 Class。

### J4 映射批准与发布（非作者审核者）
专家提交固定 `MappingRevision + SchemaFingerprint + OntologyRelease + ValidationHash + ImpactHash` 提案。审核者看增删改、身份/单位/越权/性能影响和可追溯证据；允许接受、拒绝并附原因。不同人批准；发布对当前连接版本、schema、本体Release和提案 hash 重新校验，失败则不切 active；成功激活新 MappingRelease 并提供回滚至旧不可变版本的审核路径，不改变 G3 OntologyRelease。

### J5 业务用户用语义方式查询（质量人员）
在 `语义数据探索`输入“Q235B 炉次 001 的转炉出钢与 LF 入站温度”，系统用已发布本体/词表及映射解释实体与关系；同号跨厂时先显示 `AMBIGUOUS` 候选和可识别的厂区信息，不自动合并。用户可加厂区/时间/钢种过滤；运行受控计划，返回表格/时序/谱系三种只读展示和证据栏；每个结果可定位数据源、映射版本、业务有效时间和读取水位，必要时引导 G5/G7 而不假装具备指标/根因结论。

### J6 异常、停用及恢复（管理员、用户）
凭据过期→状态 `AUTH_FAILED`，安全更新 Secret，**不盲重试**；源失联→记录 trace/重试建议，查询显示 `PARTIAL/UNAVAILABLE`；源 schema 变更→需要 revalidate，阻止错误列的活跃查询；连接停用→不允许新请求继续该源，历史 Run 仍保留快照但当前权限必须重校验；撤权→缓存/历史导出立即拒绝，不因为旧 Run 曾有数据就继续发放。

## 6. 数据源类型的动态配置（不可仅使用一个通用URL字段）
- PostgreSQL：主机、端口（预设5432，可改）、数据库、用户、Secret、TLS mode/CA、schema allowlist、连接/命令超时、只读角色验证；高级：SSL cert trust、pool上限、session时区；**不提供任意 SQL 测试输入**。
- Oracle：主机与端口或受限 Data Source Alias/Service Name（首期不直接支持任意完整 connect descriptor）、用户名、Secret、TCPS/TLS/Wallet（敏感路径交付需服务端安全挂载）、owner allowlist、连接/查询超时；支持 schema metadata 探测；**不假设 SID 与 Service Name 同义**。
- Doris：FE host、MySQL protocol port（通常9030）、catalog/database、用户、Secret、TLS选项、允许表/视图、query budgets；标识 Doris 的类型差异、catalog/time/decimal，不把 MySQL 普通模型无条件映射。
- TDengine：taosAdapter WS endpoint（默认从服务端配置产生，并非任何宿主固定值）、库、Token/Secret、WebSocket TLS、STable/子表模式、时间戳精度与时区、字段/标签、时间窗口预算；**优先 WebSocket；原生 C# 即将退场，不作为默认设计**。
- Web API：管理员登记根 origin、允许 path/method、OpenAPI JSON URL/上传式 spec（用户授权后）、鉴权方式（none/secret/OAuth2 client-credentials 授权后）、固定 header 模板白名单、Query/Path 参数白名单、数据 JSONPath 映射规则、分页策略、限流、TLS；默认仅 GET；POST 仅将来按“无副作用查询接口”的特批能力开放，绝不把 POST query 当成普遍安全。

每个类型必须有：空/加载/测试/成功/失败/权限不足/冲突/停用/编辑旧版本/重测/只读使用至少 10 种交互状态。细节见 `03-G4-UX-STATE-MATRIX.md`。

## 7. 非功能需求与 UX 完整性
- 中文界面，输入的连接参数校验错误具体到字段；不能展示未授权源名或网络内部地址。提供操作历史、帮助文案及可复制的脱敏 TraceId。
- 默认 `测试连接` 是只读分级 probe，未实际可用时显示 `PARTIAL`；密钥更新不展示旧值；敏感来源 schema 不必让不具权限的人看到。
- 长 Schema 探索与 Mapping 建议可以是持久任务（与查询 API 同步超时分离），页面关闭后继续运行，SSE/轮询可恢复；幂等和取消真实落地后才标为 PASS。
- 所有页面支持 `Loading/Empty/Error/PermissionDenied/Conflict/Stale/Partial`，动作后更新列表、面板和统计，不做只有按钮没处理器的“假交互”。
- 实验与生产路径分离，合成样本显著标明 Synthetic；无真实 Oracle/TDengine 环境的测试不得显示“5源全部 PASS”。
- 边界负例涵盖凭证泄漏、SQL read-only 绕过、SSRF、DNS rebinding、跨组织/厂区、同号误合并、时区单位错误、游标失效、源 schema 漂移、内存/行数/时间预算。

## 8. 用户典型任务「一次接入」实际最少操作设计
只要求用户手动：`选类型并填可信必填项` → `确认安全/测试范围` → `核对AI建议中的关键问题并按权限提交审核`。系统自动做连接探测、元数据发现、候选映射、版本/影响/证据整理、正常结果的可视化。发布批准是另一审核主体的明确动作，**不能为了减少点击数绕过异人审批**。

## 9. 设计是否闭环的否决条件
若实现只有“创建数据源名称”、无动态参数或测试；只有 schema 展示无映射发布；只有 Mapping 设计无 Query 消费；查询无六态/水位/授权；映射后 G3 源被改写；文档/AI 自动变成正式 Class；Docker 清理删到别的 task；则 G4 无法出关，即使所有静态测试绿灯。

## G4-00 V1.1 评审纠偏：无需额外人工配置的真实恢复流程

- 用户选择数据库类型后提交的唯一请求为 `config:{type,profile}` + `secretRef`（匿名 Web API 为 null）+ `command`。密码只通过受保护通道输入，不会作为普通 JSON 字段。首次创建修订为0。
- 映射工作台创建后由返回的 DraftId 跳转到可分享的详情地址；刷新后以固定 `GET` 恢复，不重新要求选择全部字段。审核者从固定待审列表进入不可变 Proposal 快照，查看绑定的版本、差异、校验和来源；不能靠编辑者保持当前页面。
- 六态业务结果是已经批准的统一查询概念，G4 真实源新协议 `G4QueryResultV1` 保留候选/证据/时效/观察时间和诊断；旧 G2 的发布图 EvidenceRef 不得伪装成 G4 实测证据。前端 AMBIGUOUS 必须可查看两个或以上当前获准候选并进行显式消歧。
