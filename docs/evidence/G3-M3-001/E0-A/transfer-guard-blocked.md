# ARM64 transfer guard: upload remains blocked

User could not confirm included account storage headroom and explicitly required uploads to remain blocked. This implementation adds only read-only guards, 17 tests and evidence. It does not create a confirmation proof, workflow, Action, upload, billing change or paid service. Real CLI preflight returns exit2 ACCOUNT_BUDGET_UNKNOWN with uploadPerformed=false.

Official [Actions billing](https://docs.github.com/en/billing/concepts/product-billing/github-actions) and [Actions limits](https://docs.github.com/en/actions/reference/limits) identify the minimum Free organization allowance as 500 MB; billing uses binary units, so the baseline is 524288000 bytes. Artifacts share the account pool with Packages and accrue GB-hours; public standard runner usage being free does not establish unknown account-wide artifact headroom. The script uses a separate conservative 450MiB repository ceiling and 8MiB upload overhead reserve under the approved 512MiB payload cap. Repository current inventory cannot establish owner-wide or historical billed usage.

A future explicit human confirmation would have to be registered by Master at the fixed nonsecret path docs/evidence/G3-M3-001/master/arm64-transfer-budget-proof.json with the exact schema, exact repository/owner, integer hardSpendLimitUSD=0, confirmed current remainingIncludedBytes, humanConfirmed=true, current-session source and owner-wide Actions/Packages scope. UTC age must be 0..3600s. There is no such proof now; synthetic test proofs are not approval or account observations.

The PUBLIC unauthenticated REST client performs only bounded fixed-origin GETs, disables redirects and environment proxies, sets no Authorization and reads no token variables. It validates complete bounded pagination, stable totals, unique IDs, finite sizes and public repository identity, counts expired records conservatively, and refuses a second active transfer. Preflight/validate additionally require workflow_dispatch on main, exact event/live run repository and Head, GitHub-hosted native Linux ARM64. Validate reuses actual canonical archive checks for the exact two files and producerHead, hash/input/platform identity. Unknown proof/event fields and nonempty event inputs are rejected; documented live API payloads are reduced to trusted fields.
