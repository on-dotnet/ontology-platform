## 3. 四项交付，不再新增庞大的流程框架

### A. 一份现行规则，而不是第N份补丁说明

根AGENTS只保留目标、禁止项、入口命令、角色/授权、完成标准和引用。必须显式替换“每次变更都跑全SelfTest”“每个新T从I01重开整链”等冲突。说明适用完整验收是：所有必要要求最终有有效证据覆盖，不是所有命令每次都重新运行。

现行规则优先级：本任务最新人类授权 > 现行工程政策 > 目录规则 > 通用skill示例；历史授权只约束对应历史任务。系统/平台安全限制始终不能被仓库政策覆盖。把过时的G1/M3阶段叙述移出根入口，不删历史事实。

任务交接只维护一份当前状态：目标/非目标、Base/Head、有效环境、已通过/复用/未跑门禁、失败指纹、下一动作。不要每次恢复读取八个完整会话和全部日志。

### B. 幂等环境准备与一条短真实烟测

优先抽取已验证M1能力，提供一个跨任务薄入口，建议：

```text
python3 -B scripts/maintenance/workflow.py prepare --task <TaskId>
python3 -B scripts/maintenance/workflow.py smoke --task <TaskId>
python3 -B scripts/maintenance/workflow.py plan --base <Base> --head <Head>
python3 -B scripts/maintenance/workflow.py verify --plan <受控计划>
python3 -B scripts/maintenance/workflow.py package-check --task <TaskId>
python3 -B scripts/maintenance/workflow.py closeout --task <TaskId> --dry-run
```

这些是待实现接口，不是已存在能力；允许按现有脚本风格调整文件内部组织，不能扩成服务、数据库或通用调度平台。包装器必须实际调用已有安全入口，而非只生成PASS JSON。

环境键至少涵盖OS/arch、通用及当前RID锁、global.json/SDK与MSBuild SDK来源、Node/pnpm及锁、当前真实工作树位置、Docker context/Engine、相关镜像和运行配方。区分“构建内容复用键”和“当前工作树/运行实例校验”：移动目录应重验路径敏感状态，不应盲目丢弃所有内容缓存；新Head不是必须清空环境的条件。

- 首次运行前设置私有CLI_HOME、NuGet/SDK缓存、证书首次启动策略和受控网络边界，不能先执行dotnet后再补限制。
- .NET restore验证完整当前平台锁闭包、项目包与SDK resolver路径；项目--configfile不是全部网络边界。既有隐式联网事件目录保持只读，不作为运行目录。
- pnpm/生成状态不得引用旧工作树。共享内容缓存可经核验只读复用；node_modules、bin/obj、.next等路径/平台敏感产物不得跨树无条件复制。根据锁离线链接/准备，禁止无条件 npm install 或重装。
- 同任务依赖键未变时，第二次prepare必须复用：0包下载、0SDK下载、0依赖重新物化、0无理由restore；允许必要校验和写新回执。缺失/损坏/过期身份则只重建受影响的任务私有材料。
- 工具/缓存寿命按任务或环境键，不按每个Run。Run失败保留仍有效缓存；先停不需要的自身运行资源，避免无意义长期服务。最终任务关闭才精确清理；跨任务私有runtime/凭证不复用。
- 每个Run独立fixture和输出；禁止在编译输出目录落临时数据库夹具。API实例重建后验证所有依赖者的实际连接和网络命名空间，不复用失效Web实例；不为此做无关产品网络重构。
- 正式长验收前只跑一条真实 OIDC→API→源PG→UI 动作及一个拒绝/取消路径；失败立刻进入短定位。新环境、运行拓扑变化、权限/会话改变时重跑此烟测，不能复用过去“环境在线”的结论。

本次Mac ARM64要实际验证同树重复prepare和一次隔离新树切换；Windows/Intel未运行如实标记，不为达成“全平台”临时安装。环境文件setup在新树启动时应可调用同一入口；actions用于prepare/smoke/按影响验证，不照抄官网联网安装示例。

### C. 按影响验收是默认路径，有机械防线

每个gate登记其传递依赖：产品源码、测试/断言与预期、驱动/辅助SQL、生成器、配置、锁与工具、相关平台、镜像/fixture配方及权限边界。脚本位于docs/evidence也要绑定；不能只按扩展名或顶层目录决定无影响。

门禁输入键不得只等于HEAD或RunId。HEAD是审计归属；相同内容可来自不同提交。变更只使依赖它的门禁失效，传播到有依赖的消费者。未映射的高风险变更应拒绝宣称覆盖，扩展到安全的相关检查范围；不静默放行，也不默认为了省事把全部项目永久设为受影响。

复用条件：原命令真实成功、测试覆盖/skip符合当时要求、原始证据不可变可恢复、输入键相同、适用环境/策略仍兼容、无新缺陷推翻旧结果。输出原T/Run、证据SHA、输入键、复用理由与当前核验命令。实际执行与复用分别展示；不得把复用写成“本轮测试exit0”。

保留既有V3/schema2枚举兼容：在单独impact清单或允许的metadata记录 `executionMode=FRESH|REUSED`，不能把新 `REUSED_PASS` 随意塞进旧schema的status枚举。

最少覆盖下列规则：

| 变化 | 默认新验证 | 允许复用 |
|---|---|---|
| 纯文档措辞、非执行说明 | 文档/链接/规则一致性，交付绑定 | 无关产品测试 |
| 前端组件/状态逻辑 | 相关组件测试、Web检查、相关真实交互与权限/取消回归 | 未变后端/迁移/SDK恢复 |
| 仅I07浏览器驱动 | 驱动测试和I07受影响场景 | I02/I05等无依赖检查 |
| REST/DTO/生成器/授权或共享配置 | 合同及传递消费者、安全/生成链/相关集成 | 有证据证明无关的模块 |
| SDK/RID锁/镜像/fixture语义变化 | 对应环境准备、构建和依赖其结果的测试 | 不依赖该环境的检查 |
| 只有打包器/证据裁剪变化 | 打包器正反、旧包兼容、来源完整性/大小 | 产品运行结果 |

默认按程序集/夹具组批量执行，不为每个用例启动进程；有实际共享状态污染证据的组保留必要隔离，不盲目改变既有测试安全性。零测试、失败、跳过不等于通过；原260跳过必须保持其最终闭合来源，不能丢弃历史。

失败指纹=(相关输入键、构建、平台/环境、错误类型)。相同指纹、无新假设/无条件变化时，拒绝再次启动昂贵链；短诊断仍允许。连续3次同类修复失败，停止扩写工具，输出最小复现和机制性修订意见；并非把3次当全项目永久失败阈值。确认瞬态/波动才做有上限的复测并保留全部结果，禁止把反复跑到绿算成功。

阶段结束完整性判定：全部必要gate都由FRESH或有效REUSED覆盖，再做小范围当前状态/集成烟测和独立Review；不是新T全部清零。确有系统性输入变化、依赖关系不可信或发布政策要求时，明确理由后跑对应完整验收。

### D. 提前交付检查、单份证据、一次独立审查
