# 本地优先、按需 CI 的跨平台验证政策

生效日期：2026-10-29（Asia/Shanghai）。依据：人类在侧聊明确批准快速开发以本地真实验证为主，并要求与当前执行任务同步、永久写入仓库，供 Windows、macOS、Linux 开发共同遵守。

本政策覆盖现行 AGENTS、PLANS、效率、生命周期、任务和构包规范中“每次提交、增量集成、资源收尾或最终交付均必须等待 GitHub Actions 同 Head CI”的默认要求。历史授权、已交付审查包、原始运行记录和失败事实保持原样；当前及后续开发使用本政策，除非人类后来明确指定某项远程 CI 为必要门禁。

## 开发与集成

- 日常修改先执行受影响的静态、单元、契约或组件测试；真实服务使用本机已批准的 Docker 环境。失败先廉价定位，仅重跑受影响层。
- 可运行切片经真实验证和独立审查后，由 Master 按现有 Git/Worktree 规则增量集成。提交、push、文档或证据变更不自动要求一轮完整 GitHub Actions。
- 稳定产品源码在本地完成适用的完整验收一次，包含实际构建、真实数据库/语义服务和必要的浏览器、权限、发布、回滚、兼容性与资源检查。容器启动、Mock 或零测试不能替代产品验收。
- 已通过的验证可以在产品源码、锁文件、构建配置和相关运行输入未变化时复用。记录原测试提交、当前交付提交及输入一致性依据；纯文档或证据提交不机械触发无关全量重验。存在相关变化、失败或未解决疑点时补跑受影响层。

## GitHub Actions 与交付

- GitHub Actions 为按需的远程补充验证，快速开发默认手动触发，不因每个 push、PR 或证据增量重复运行全部工作流，也不作为默认的本地集成、资源回收或最终交付前提。显式的任务目标或后续人类授权可要求指定 CI。
- 本地验收、独立 Review、已提交源码及输入绑定、完整 diff、唯一 Review ZIP V3 和独立重开仍为交付门禁。构包必须支持明确的本地验证来源，不因缺少 GitHub runId 阻断已满足本地门禁的交付；不能仅改文字而保留隐藏的强制 CI 查询。
- CI 已运行则保留真实 runId、URL、Head 和结果；未运行或不可核实分别如实记录 NOT_RUN/NOT_VERIFIED。本地 PASS 与云端 CI 状态分列，本地通过不伪造云端 PASS，也不掩盖已知失败。历史审查包继续按其原合同校验，不改历史 SHA。
- 真正验证 CI 功能的任务仍需对应的真实远程证据。例如跨 runner 缓存复用不能用两次本地 Docker 运行冒充；已有有效的 cold/warm 证据在相关输入未变时复用，不为普通业务或文档变更重复证明。
- 已运行的本地浏览器、容器和测试允许正常完成 finally 回收；保留既有失败和 CI 记录。费用、制品上传、外部依赖、权限及分支保护仍服从原授权，本政策不扩大这些权限。

## Windows、macOS、Linux 共用约束

- 使用项目已锁定并由既有 bootstrap/doctor 确认的工具链及批准依赖；不改机器默认 SDK、PATH、全局工具、系统 Docker 或 WSL 配置。
- 新增和修改的脚本采用标准路径/临时目录 API、显式编码、正确参数传递和可用解释器；不写死 `/private/tmp`、盘符、用户目录、路径分隔符或系统特有命令。路径、换行、大小写和进程退出行为按实际受影响平台验证。
- Docker 运行的服务平台与开发宿主平台分开记录。Linux 容器通过不自动证明 Windows/macOS 宿主脚本可用；未实测宿主、架构或平台写 NOT_RUN，不用另一平台的结果代替。
- 换机只执行必要的环境检查及平台相关验证，复用输入一致且与宿主无关的既有事实；不因换到 Windows 开发就恢复每次提交等待云端全量 CI 的旧流程。
- 资源回收继续要求准确归属、白名单、指纹/期限、实时引用重验、独立审查、真实 before/after 和强后验。平台不具备安全删除能力时明确拒绝该项，保留准确对象和解除条件，不能用不安全 fallback 或全局清理追求通过。

落实入口：根 AGENTS.md、PLANS.md、当前授权、[效率规则](ai-development-efficiency.md)、[生命周期](resource-lifecycle.md)、[Review ZIP 合同](review-package-spec.md)及其执行器由 Master 统一同步本政策；阶段性脚本和自动回归应验证本地路径可交付、CI 事实不被伪造、旧包仍可复检。
