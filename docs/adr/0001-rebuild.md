# ADR 0001：推倒重建，不在旧代码上改造

- 状态：已采纳（2026-11-22）
- 决策人：项目所有者

## 背景

旧版本（.NET 10 + Next.js，由多个 AI 代理按"任务卡 + 证据回执"流程开发）在 2026-11 停在 G4 阶段，核心问题：

- 受跟踪文件约 2.4 万个，其中 98% 是验收证据；流程脚本约 4 万行，与后端代码量相当。
- 数据连接模块约 1 万行，但目标地址被写死为测试夹具，无法连接真实数据库；五类数据源各写一套，按源类型分支散落在多个文件中。
- 本体编辑只能逐条改三元组，复杂 OWL 无法编辑或发布；文档知识、AI 分析、指标规则没有可用代码；没有接入真实大模型。
- 界面把过程信息直接输出到页面。

## 决策

在同一仓库的 main 上重建。旧代码完整保存在标签 `archive/main-before-rebuild`，旧分支保存在 `archive/codex/*` 标签。

保留的是设计思路，而不是代码：发布与回滚模型、对外部数据源只读、单位与身份时间规则、钢铁冶金样例与 OWL 特性样例（`samples/`）。

废除旧的研发流程：V3 审查包、非作者重开、包外回执、资源生命周期回执、证据入库。改为"短分支 + PR + 容器内门禁 + 复审"。

## 理由

- 数据源、查询、本体编辑、界面、AI 都需要重做，旧代码能直接留用的不到两成。
- 没有生产用户和数据，不需要承担历史兼容。
- AI First 让"证据、候选、变更集"成为核心模型，在旧结构上叠加比重建更贵。

## 影响

- 旧的 506 个后端测试与旧合同不再适用；新代码按新的接口约定重新建立测试。
- 不重写 Git 历史，仓库 `.git` 体积暂不缩小。
