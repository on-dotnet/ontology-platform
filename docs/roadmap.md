# 路线图

基调是 AI First：先让"给资料 → AI 识别 → 人工确认"跑通，再补齐手工建模、数据绑定和分析。每个里程碑都以用户能完成的事情为完成标准。

| 里程碑 | 用户能做什么 | 完成标准 |
|---|---|---|
| **M0 新地基** | 登录平台，看到统一风格的工作台（深浅主题、中英双语） | 10.16.0.13 上 `./dev.ps1 up` 后可登录；`./dev.ps1 ci` 全部通过；架构、界面规范、研发规则就位 |
| **M1 AI 资料 → 本体** | 上传资料，AI 分阶段识别术语、对象类型与层级、关系，生成带证据的变更集；逐项审核后发布第一版本体；导出 Turtle | 用钢铁冶金样例资料从零生成一版本体并发布；评测集有准确率、召回率基线 |
| **M2 本体工作台** | 手工维护全套本体：属性（类型、单位、必填、基数）、关系、层级、约束、中英术语；专家模式编辑 Turtle 与高级公理；用自然语言让 AI 改本体；版本对比与影响分析 | `samples/owl-features` 全部能导入再导出不丢内容；与 Protégé 往返一致 |
| **识别质量**（M3 之前） | AI 识别得更准、更快：识别出的概念与已有元素对齐，不产生重复 | 评测地基（#39）：录制与回放、属性与层级计分、第二个案例包、基线；对齐改造（#40，含 #36）：实体消解、输出精简提速 |
| **M3 数据绑定与查询** | 连接 PostgreSQL 数据库，AI 建议对象类型与表、属性与列、关系与外键的绑定，审核发布后生效；按本体浏览对象、沿关系遍历，结果带来源；外部智能体用访问令牌经 MCP 读取本体、查询对象、提议变更 | PG 中的冶金样例数据可按本体查询（[规格 003](specs/003-m3-data-binding-query.md) 第 1 节的验收路线） |
| **能力问题** | 用户先写下本体要能回答哪些问题 | 另出规格时确定 |
| **M4 AI 分析** | 用自然语言提问，AI 调用本体、数据、资料回答并给出出处、假设与反证；最小可用的指标与规则；问答发现的缺口回流为变更提议 | Q235B 钢卷质量异常分析端到端演示 |
| **M5 开源发布** | 新用户 10 分钟内跑起来并用案例包体验 | 中英文 README、快速上手、文档站、贡献指南、案例包；可选的企业 OIDC 接入及统一风格的 Keycloak 登录主题（Keycloakify）；MCP 的 OAuth 2.1 授权 |

## 对路线图的调整（议题 #41）

用户把项目交给主会话推进后，评审对路线图做了以下调整（总计划与进度见议题 #41）：

- **识别质量先于 M3**：评测地基（#39）和对齐改造（#40，含 #36）排在 M3 之前。
- **M3 只做一种数据库**：连接器统一接口加 PostgreSQL 连接器。Oracle、Doris、TDengine、Web 连接器移出 M3，见下面的"有环境后再做"。
- **MCP 分两步**：先做只读工具加访问令牌，"提议变更"工具放在 M3 最后一批。完整的 OAuth 2.1 授权与企业 OIDC 一起放 M5。
- **数据绑定按元素存储、走变更集审核**，随发布版本固化；R2RML 只作导出，不做通用的 R2RML 转 SQL。M3 不引入 SPARQL 和 Oxigraph。理由见 [ADR 0003](adr/0003-data-binding-and-external-access.md)。
- **能力问题提前**到对齐改造之后。
- **前端工具链只做小步升级**：ESLint 10、TypeScript 6；TypeScript 7 与 oxlint 等到 7.1 的编程接口稳定后再评估。

## 有环境后再做

- **Oracle、Doris、TDengine 连接器**：M3 的连接器接口按"语句生成和目录发现只实现一次"设计，加一种数据库只需要补方言、驱动和连接层的只读设置。每一种都要有能实测的环境才动手，不写只靠模拟测试的连接器。Doris 还要等 Docker 主机的 CPU 升级。
- **Web 连接器**（HTTP 数据源）：同样等有真实的接口可测时再做。

## 已知前提与待办

- **Docker 主机 CPU**：10.16.0.13 目前只有 x86-64-v1 指令集，Doris 无法运行，NumPy 2.4 及以上会崩溃。用户正在与管理员协调把虚拟机 CPU 改为 host-passthrough。改好之前依赖选型避开这些包。
- **OpenAI 访问**：Docker 主机无法直接访问 api.openai.com。M1 开工前需要确定容器访问模型的方式（代理或中转），API Key 由用户本人写入不入库的配置文件。
- **GitHub Actions**：账户无额度，门禁以 `./dev.ps1 ci -Report` 写入的提交状态 `local-ci` 为准。
