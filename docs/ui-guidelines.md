# 界面规范

所有页面都按本规范实现，评审时按第 12 节逐条走查。视觉风格参考 TailwindAdmin（Next.js Dark 演示）的彩色企业后台风格，组件与样式独立实现，不复制任何模板源码。

## 1 原则

1. **只给用户需要的信息。** 页面上不出现过程信息：原始 JSON、哈希、内部状态码、调试日志、接口路径、任务 ID 都不上页面。确实需要排查时，放进默认折叠的"技术详情"。
2. **条理清晰。** 每个页面只有一个主任务，一个区域最多一个主按钮。
3. **AI 的产出看得出、管得住。** AI 生成的内容统一标识，写操作一律经审核卡片才生效。
4. **状态完整。** 每个数据区域都要处理加载、空、出错、无权限四种状态。
5. **中英双语、深浅双主题、可键盘操作。**

## 2 主题与设计令牌

主题有三种：浅色、深色、跟随系统（默认）。用户的选择保存在浏览器本地。令牌以 CSS 变量定义在 `web/src/styles/globals.css`，组件只用令牌，不写死颜色值。

| 令牌 | 浅色 | 深色 | 用途 |
|---|---|---|---|
| `--background` | `#f5f8fc` | `#151d2b` | 页面底色 |
| `--card` | `#ffffff` | `#1c2536` | 卡片、面板、侧栏 |
| `--muted` | `#eff4fa` | `#2a3851` | 次级底色、表头、悬停 |
| `--border` | `#e5eaef` | `#333f55` | 分割线、边框 |
| `--foreground` | `#2a3547` | `#eaeff4` | 正文 |
| `--muted-foreground` | `#5a6a85` | `#7c8fac` | 次要文字、说明 |
| `--primary` | `#3f6ae8` | `#3f6ae8` | 主按钮、焦点环、选中态（由品牌色 `#5d87ff` 加深，保证白字对比度 ≥ 4.5:1） |
| `--secondary` | `#49beff` | `#49beff` | 辅助强调 |
| `--success` | `#13deb9` | `#13deb9` | 成功 |
| `--warning` | `#f6b51e` | `#f6b51e` | 注意 |
| `--error` | `#ef4444` | `#f87171` | 错误、危险操作 |
| `--info` | `#8754ec` | `#a07cf5` | 信息、AI 标识 |

每个语义色另有两个派生令牌：

- `-soft`：淡底，用于彩色统计卡片、标签和提示条背景（基于品牌原色，浅色主题约 10% 透明度、深色主题约 15%；主色淡底基于 `#5d87ff`）。
- `-strong`：同色相的文字与图标色，用于淡底上的文字、链接和选中的导航文字；浅色主题加深、深色主题提亮，保证小字对比度满足 WCAG AA。语义原色（如 `--success`）不直接用作小字颜色。

另有 `--primary-foreground`（主按钮文字）、`--primary-hover`、`--ring`、`--overlay`（遮罩）、`--card-shadow`、`--popover-shadow`。

- **字体**：`"DM Sans", "PingFang SC", "Microsoft YaHei", "Noto Sans SC", system-ui, sans-serif`；正文 14px，行高 1.6。标题 24 / 20 / 16px，字重 600。数字用等宽数字（`tabular-nums`）。
- **圆角**：卡片 12px，按钮与输入框 8px，标签 6px。
- **间距**：以 4px 为单位；页面内边距 24px，卡片内边距 20px，区块间距 24px。
- **阴影**：浅色主题卡片用轻阴影；深色主题不用阴影，用边框区分层次。

## 3 布局

```
┌────────────┬──────────────────────────────────────────────┐
│  标志       │ 顶栏：面包屑            搜索  ✦AI  语言 主题 用户 │
│            ├──────────────────────────────────────────────┤
│  导航       │ 页面标题  ⓘ                       主操作按钮  │
│            │                                              │
│            │ 内容区                              ┌────────┐ │
│            │                                     │AI 助手 │ │
│            │                                     │(可收起)│ │
└────────────┴─────────────────────────────────────┴────────┘
```

- 侧栏宽 256px，可收起为 72px 的图标栏；窄屏（< 1024px）变为抽屉。
- 顶栏高 64px。全局搜索在平台有可搜索的内容后再加入，之前不放占位按钮。
- **未实现的功能**：导航项和面板入口可以先放，打开后显示"即将推出"的空状态，说明将来能做什么；但不得出现"做某件事"却被禁用的操作按钮，也不得用文案断言数据现状（如"还没有数据"）而背后没有查询。
- AI 助手是右侧可收起的面板，任何页面都能打开（快捷键 `Ctrl/⌘ + J`），它知道用户当前所在页面和选中的对象。

导航按任务组织，共 8 项：

| 导航 | 内容 |
|---|---|
| 工作台 | AI 输入框（上传资料或描述业务）、待审核事项、最近动态 |
| 资料 | 上传、解析状态、AI 识别结果 |
| 审核 | 变更集列表与逐项审核 |
| 本体 | 图谱视图、列表视图、元素详情；专家模式 |
| 数据 | 数据源连接、表目录、数据绑定 |
| 探索 | 对象浏览、关系遍历、AI 问答 |
| 版本 | 发布记录、版本对比、回滚 |
| 设置 | 模型、成员与角色、平台参数 |

## 4 提示信息分级

| 级别 | 形式 | 何时用 |
|---|---|---|
| 说明 | 标题或字段旁的 **ⓘ 图标**，悬浮或键盘聚焦时显示气泡 | 解释概念、字段含义、操作后果；不看也能完成任务的信息 |
| 注意 | **! 图标**（黄色），悬浮显示 | 可能出乎意料但不影响结果的情况 |
| 注意（重要） | 页面内的**黄色提示条** | 会影响结果、用户必须知道的情况，例如"该版本发布后，3 个数据绑定将失效" |
| 错误 | 页面内的**红色提示条**，或字段下方的红字 | 操作失败、输入不合法。必须写清"出了什么问题"和"怎么办" |
| 成功 | 右下角轻提示（3 秒自动消失） | 操作完成；可撤销的操作在轻提示里给"撤销" |

- 图标气泡里只写一两句话；超过三句的内容改成"了解更多"链接。
- 不在页面上常驻大段说明文字。
- 错误文案由前端根据后端返回的错误码生成，不直接展示后端原文或堆栈。

## 5 页面状态

| 状态 | 表现 |
|---|---|
| 加载 | 骨架屏，保持最终布局；超过 10 秒显示"仍在处理"及取消按钮（如可取消） |
| 空 | 插图或图标、一句说明、一个下一步主按钮（如"上传第一份资料"）。另有同样常用的起步方式时，可以再放一个次要按钮（如"导入 OWL 文件"），不再多 |
| 出错 | 红色提示条：原因、建议、"重试"按钮；技术详情折叠 |
| 无权限 | 说明需要什么角色、找谁开通；不显示数据的任何片段 |

## 6 文案

- 使用统一术语：对象类型、属性、关系类型、术语、约束、变更集、审核、发布、版本、数据源、数据绑定。不混用"实体/类/概念"等同义说法。
- 按钮用动词开头："发布版本""上传资料"，不用"确定""提交"这类泛称（对话框底部除外）。
- 中文界面使用中文标点；数字、英文与中文之间不强制加空格，同一页面保持一致。
- 时间显示为本地时间，近期用相对时间（"3 分钟前"），悬浮显示完整时间。

## 7 AI 交互

- **标识**：AI 生成的内容带 `✦ AI 建议` 标签（`--info` 色），附置信度（高 / 中 / 低，悬浮显示百分比）和证据链接。点击证据时打开原文，并高亮对应片段。
- **只提议，不直接改**：AI 的写操作都生成变更集，用户在审核卡片上逐项接受、修改或拒绝。
- **进度**：长任务显示步骤级进度（"解析资料 → 识别术语 → 识别类型与层级 → 识别关系"），不滚动输出日志。任务可以停止。
- **对话**：回答中引用的对象、资料、数据都是可点击的链接；不确定时明确说出不确定，并给出依据。
- **失败**：模型不可用或超时时，说明影响范围（"AI 识别暂不可用，已上传的资料不受影响"），并给出重试入口。

## 8 操作与表单

- 危险且不可撤销的操作（删除、回滚发布）用确认对话框，写清后果；可撤销的操作不弹确认，改为轻提示加"撤销"。
- 表单字段标签在上，必填项在标签后加 `*`；校验在失焦时进行，提交时汇总到表单顶部。
- 只有图标的按钮必须有悬浮文字和 `aria-label`。

## 9 表格与列表

- 默认紧凑行高（40px），表头吸顶；数字右对齐，文本左对齐。
- 列表超过 50 条时分页或虚拟滚动；筛选条件显示为可移除的标签。
- 行内操作不超过 2 个，更多操作收进"⋯"菜单。

## 10 可访问性

- 文字与背景对比度满足 WCAG AA（正文 4.5:1）。
- 所有交互元素可用 Tab 访问，焦点有明显的 `--primary` 色焦点环。
- ⓘ 与 ! 图标是可聚焦的按钮，键盘聚焦时同样显示气泡。
- 颜色不是唯一的信息载体：状态同时用图标或文字表达。

## 11 国际化

- 所有界面文字通过 i18n 键取得（`web/src/i18n/locales/zh-CN.json`、`en.json`），组件里不写死中文或英文。
- 默认语言跟随浏览器，无法识别时用简体中文；用户可在顶栏切换并保存。

## 12 走查清单

提交界面改动的 PR 前逐条确认，并在 PR 里附深浅两种主题的截图：

- [ ] 页面上没有过程信息（JSON、哈希、状态码、ID、日志）
- [ ] 每个数据区域都有加载、空、出错、无权限状态
- [ ] 提示信息按第 4 节分级，说明类信息用 ⓘ 而不是常驻文字
- [ ] 一个区域最多一个主按钮，按钮文字以动词开头
- [ ] AI 内容有标识、置信度和证据入口，写操作经审核
- [ ] 只用设计令牌，没有写死的颜色；深浅两种主题都检查过
- [ ] 所有文字都走 i18n，中英文切换后布局不乱
- [ ] 键盘能完成主要操作，焦点可见，图标按钮有 `aria-label`
