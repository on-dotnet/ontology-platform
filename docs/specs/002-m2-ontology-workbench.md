# 002 M2：本体工作台

- 级别：L2。涉及数据库迁移、手工编辑的写入路径与审核模式、AI 助手的写入路径，以及 `dev.ps1` 新增命令。
- 关联：[架构](../architecture.md)、[界面规范](../ui-guidelines.md)、[路线图](../roadmap.md)、[001 M1](001-m1-ai-ingestion.md)、[接口附录](002-m2-api-shapes.md)

## 1 用户能做什么

1. **手工维护本体**：在"本体"页新建、修改、删除对象类型、关系类型、属性和约束：
   - 属性：数据类型、单位、必填、允许多个；
   - 关系：定义域、值域、必填、允许多个、互逆；
   - 对象类型：父类型；
   - 约束：每个对象类型的校验规则，如取值范围、枚举取值、正则、提示信息，导出为 SHACL；
   - 每种元素都可维护中英文名称、定义和同义词。

   修改元素前可以看到影响范围；多人同时修改同一元素时不会互相覆盖。
2. **导入 OWL**：上传 Turtle 或 RDF/XML，新建本体或导入到已有本体。能映射的内容成为元素；映射不了的作为高级公理原样保留，导出时不丢。
3. **专家模式**：查看和编辑整份工作版本的 Turtle，或者逐条编辑高级公理。保存时平台算出差异，生成变更集。
4. **用自然语言让 AI 改本体**：在右侧 AI 助手面板里描述要改什么，助手生成待审核的变更集。
5. **版本对比与影响分析**：对比任意两个版本，或某个版本与工作版本，标出不兼容的变更；发布前先看到相对当前版本改了什么。

验收（路线图）：

- `samples/owl-features` 全部能导入再导出，不丢内容；
- 与 Protégé 往返一致（第 4.3 节）。

另外，第 1–5 项都要在开发栈 http://10.16.0.13:28080 上实际走通。

## 3 本体模型的扩展

### 3.1 元素

`ontology.elements` 新增两种 `kind`：

- `constraint`：约束，对应一个 `sh:NodeShape`（第 3.3 节）；
- `axiom`：高级公理，是原样保存的 Turtle 片段（第 3.4 节）。

新增的列：

| 列 | 说明 |
|---|---|
| `iri` | 显式 IRI，可空。为空时 IRI = `base_iri + local_name`（沿用 M1）。导入的元素保存原 IRI。显式 IRI 与推导出的 IRI 合起来，在同一本体内唯一（服务层校验） |
| `inverse_id` | 仅关系：互逆关系，导出为 `本关系 owl:inverseOf 对方` |
| `rules` | 仅约束：jsonb 规则列表（第 3.3 节） |
| `turtle` | 仅公理：Turtle 片段，不含前缀声明 |
| `subject_id` | 仅公理：片段的命名主语是本体里的元素时指向它，用于在元素详情里列出相关公理 |
| `flags` | jsonb 数组；目前只有 `non_standard`（第 3.4 节） |

放宽的约束（上一版程序写入的数据仍然满足）：

- **名称**：`label_zh` 可空，因为导入的元素可能没有中文名。平台内新建的元素仍要求中文名，由接口校验。界面按中文名、英文名、IRI 局部名的顺序取第一个有值的显示。
- **局部名**：公理的 `local_name` 为空，其他种类仍然必填且唯一。导入的元素用 IRI 末段生成局部名：只保留字母和数字，以字母开头，重名时加序号。有显式 IRI 的元素不检查 PascalCase 和 camelCase 约定。
- **引用与类型**：关系的定义域、值域，属性的定义域、数据类型都改为可空，因为 OWL 允许不写。钢铁样例的 `op:externalId` 就没有定义域。
- **删除**：`status = deprecated` 表示"已删除"。已删除的元素不导出、默认不列出，可以恢复；它的 IRI 和局部名仍然被占用。
- **来源**：`origin` 增加 `import`，用于导入生成的元素。

各种类可以使用的列：

| kind | 用到的列 |
|---|---|
| `entity_type` | `parent_id` |
| `relation_type` | `domain_id`、`range_id`、`inverse_id`、`required`、`multiple` |
| `property` | `domain_id`、`datatype`、`unit`、`required`、`multiple` |
| `constraint` | `domain_id`（目标对象类型，必填）、`rules` |
| `axiom` | `turtle`（必填）、`subject_id` |

### 3.2 本体与版本

- `ontology.ontologies` 新增两列：
  - `ontology_iri`：可空，为空时取 `base_iri` 去掉末尾的 `#` 或 `/`（沿用 M1）；
  - `prefixes`：jsonb，保存导入文件里的前缀，导出时沿用。
- `ontology.releases` 新增 `header` 列（jsonb：本体 IRI 与前缀），保证旧版本重新导出时结果不变。快照里包含全部种类的元素。

### 3.3 约束

一个约束元素对应一个 `sh:NodeShape`，各部分的对应关系：

| 约束元素 | SHACL |
|---|---|
| IRI | 形状的 IRI |
| `domain_id` | `sh:targetClass`，必须是本体里的对象类型 |
| 中英文名 | `rdfs:label` |
| `rules` 里的每一条 | 一个 `sh:property` |

一条规则可以包含的字段：

- 必填：`path`，指向一个属性或关系元素；
- 数量：`minCount`、`maxCount`；
- 取值类型：`datatype`、`class`（对象类型）、`nodeKind`；
- 取值范围：`in`（枚举）、`minInclusive`、`maxInclusive`、`minExclusive`、`maxExclusive`；
- 字符串：`minLength`、`maxLength`、`pattern`、`flags`；
- 提示信息：`message`（带语言）。

规则中的取值保留原写法，结构见附录的 `RdfValue`。

形状里出现上面之外的写法时，整个形状作为一条公理原样保留，界面提示可在专家模式里编辑。例如 `sh:or`、复杂路径、`sh:closed`、`sh:sparql`、多个目标类。

M1 的自动形状（`{类型}-shape`）继续保留：平台内新建的对象类型照旧生成这个形状（包括没有成员的空形状），其属性和关系的"必填""允许多个"写在里面。元素是否参与自动形状记在 `auto_shape` 列：平台内新建的元素都参与；导入的元素只有在文件里本来就有这样的形状时才参与，导出时不会给导入的本体凭空加上 SHACL 规则。

### 3.4 高级公理

**拆分规则：**
- 一条公理是"一个命名主语的一个三元组"，再加上从它的宾语出发能到达的全部空白节点，例如 `C rdfs:subClassOf [ 限制 ]`、`C owl:disjointWith D`、`i a C`、一条注解。
- 不从命名主语出发的空白节点结构（如 `[] a owl:AllDisjointClasses ; owl:members ( … )`）各自成为一条公理。
- 同一个空白节点被多处引用时，读入时按引用拆开，每处各存一份。OWL 2 本来就不共享匿名结构；拆开后，Protégé 存回的文件与原文件可以逐条对上。只有成环的空白节点保持原样，连在一起的语句合成一条公理。

**存储与比较：**
- 公理存为 Turtle 片段，用本体的前缀书写，保存和导出时都保留原写法。
- 比较时用规范形式：空白节点按 rdflib 的规范标号；类型化字面量按值比较，例如 `"01"^^xsd:integer` 与 `"1"^^xsd:integer` 视为相同。

**关联：**
- 主语是元素时，用 `subject_id` 关联到该元素。
- 主语是本体 IRI 时，作为本体注解，例如 `owl:imports`、`owl:versionIRI`。

**`non_standard` 标记：** 标在 OWL API（也就是 Protégé）读入时会改写的写法上。界面用 ! 图标提示"在 Protégé 中打开时会改写这条公理"。包括：
- 命名类直接带 `owl:unionOf`、`owl:intersectionOf`、`owl:complementOf` 或 `owl:oneOf`（会被改写为等价类）；
- 基数限制的值不是 `xsd:nonNegativeInteger`（会被读成错误类）。

### 3.5 变更项

- `op` 新增 `delete`（把目标元素设为已删除）和 `restore`（恢复已删除的元素）。两者都要求 `target_element_id` 与 `target_revision`。`restore` 可以同时带上要修改的字段，避免恢复后同一元素的修改项因 revision 变化而被跳过。
- `kind` 新增 `constraint`、`axiom`。
- `proposed`、`edited` 新增五个键：
  - `iri`；
  - `inverseRef`；
  - `autoShape`；
  - `rules`：规则里的 `pathRef`、`classRef` 写元素 id 或 `temp_ref`；
  - `turtle`。

  公理所属的元素（`subject_id`）在合并时按片段的主语 IRI 自动关联，不需要引用。
- `change_sets.source` 新增 `import`。
- **同义词**：导入和手工编辑的同义词列表按给定列表替换；AI 识别的同义词沿用 M1 的做法，追加到已有列表里。
- **合并规则补充：**
  - **顺序**：先应用 create、update、restore，最后应用 delete；删除时先删依赖方。
  - **依赖检查**：应用完本变更集里其他已接受的项之后，如果仍有在用（active）的元素引用要删除的元素，该删除项跳过，`code` 为 `changeset.has_dependents`。引用包括父类型、定义域、值域、互逆、规则路径、公理主语。
  - **公理与约束**：公理项和约束项按第 3.3、3.4 节校验，不合法的跳过（`changeset.invalid_item`）。

## 4 导入与导出

### 4.1 导入

**限制：**
- **格式**：支持 Turtle（`.ttl`）和 RDF/XML（`.owl`、`.rdf`、`.xml`），以内容检测为准。
- **大小**：文件不超过 5 MB，三元组不超过 50,000 个；单条公理不超过 200 万字符（`import.axiom_too_large`）。超出接口字段上限的内容（如超长的同义词表、规则表）不进表单，作为公理保留。
- **不联网**：`owl:imports` 只保留，不加载；RDF/XML 不解析外部实体。
- **保留字面量写法**：关闭 rdflib 的字面量规范化（`rdflib.NORMALIZE_LITERALS = False`）。

**两种导入目标：**
1. **新建本体**：`POST /api/ontologies/import`。
   - 名称：可以不填，默认取文件里本体的无语言 `rdfs:label`，再不行就用文件名。填了名称时，文件里不同的名称作为本体注解保留。
   - key：可以不填，由名称生成；已被占用时自动加序号，同一个文件可以导入多次。
   - 本体 IRI：取文件中 `owl:Ontology` 的 IRI。
   - `base_iri`：取元素最多共用的命名空间。

   导入生成一个来源为"导入"的变更集。
2. **导入到已有本体**：`POST /api/ontologies/{id}/import`。把文件内容与工作版本比较（第 5 节），用差异生成变更集。专家模式保存整份 Turtle 也走这条路径。
   - 文件里本体的名称和描述只有与平台里相同时才被吸收；不同的作为本体注解（公理）进入变更集，不会悄悄丢掉。
   - 同一本体的导入、合并、发布依次进行（锁住本体行），变更集里公理片段用到的前缀不会被同时进行的导入改掉。

**映射规则：**

| 文件里的内容 | 平台里的结果 |
|---|---|
| `X a owl:Class` | 对象类型。W3C 词汇的命名空间（rdf、rdfs、owl、xsd、sh、skos、dcterms、prov、time 等）里的 IRI 除外 |
| `X a owl:ObjectProperty` | 关系类型 |
| `X a owl:DatatypeProperty` | 属性 |
| `rdfs:label "…"@zh` / `"…"@en` | 中文名 / 英文名，每种语言取按字面排序的第一个；其余标签作为公理 |
| `skos:definition "…"@zh` / `"…"@en` | 定义（规则同上） |
| `skos:altLabel "…"@zh` / `"…"@en` | 同义词 |
| 对象类型恰好有一个命名的 `rdfs:subClassOf`，且目标是对象类型 | 父类型；有多个时全部作为公理 |
| 关系或属性恰好有一个命名的 `rdfs:domain`，且是对象类型 | 定义域；否则作为公理 |
| 关系恰好有一个命名的 `rdfs:range`，且是对象类型 | 值域；否则作为公理 |
| 属性恰好有一个 `rdfs:range`，且是平台支持的 6 种 xsd 类型之一 | 数据类型；否则作为公理 |
| `op:unit "…"` | 单位 |
| `p owl:inverseOf q`，p、q 都是关系 | p 的互逆关系 |
| IRI 为 `{类型 IRI}-shape` 的 `sh:NodeShape`，且内容与平台自动生成的一致 | 吸收为属性和关系的"必填""允许多个" |
| 其他 `sh:NodeShape`，且只用到第 3.3 节支持的写法 | 约束 |
| 平台的派生三元组（第 4.2 节） | 吸收，不单独存储 |
| 其余全部三元组 | 高级公理（第 3.4 节） |

**只被用到、没有声明的实体**：按 OWL API 的方式确定种类（规则同第 4.2 节的声明推断），并照常成为元素。例如样例 06 里只出现在定义域、值域中的 A、B、C 会成为对象类型。Protégé 打开文件时也是这样理解的，存回的文件会带上这些声明；这样读入以后，两边一致。

**导入后的默认值：**
- 关系和属性如果没有被平台自动形状覆盖，"必填"设为否、"允许多个"设为是。这是 OWL 开放世界的默认语义，导出时不会凭空加上 `sh:maxCount 1`。
- 导入生成的变更项不带置信度和证据；`non_standard` 公理带标记。
- 审核页对"导入""手工"两种来源提供"接受全部"。

### 4.2 导出

工作版本和各版本的导出由同一个函数从"本体状态"生成。在 M1 的基础上补充：

- **元素与公理的写法**：
  - 有显式 IRI 的元素用显式 IRI；
  - 公理按原文写出；
  - 约束写成 `sh:NodeShape`；
  - 互逆写成 `owl:inverseOf`。
- **派生三元组**：导出时生成，导入时吸收，有三类：
  1. **本体头**：`owl:Ontology`、名称 `rdfs:label`、`dcterms:description`、版本导出里的 `owl:versionInfo`，以及 `dcterms:created`。如果导入文件自带 `owl:versionInfo` 或 `dcterms:created`，它们作为本体注解保留，导出时用保留的值，不再生成。
  2. **声明**：文件里用到但没有声明的实体，按 OWL 2 的要求补上声明（`owl:Class`、`owl:ObjectProperty`、`owl:DatatypeProperty`、`owl:AnnotationProperty`、`owl:NamedIndividual`），这样 Protégé 读入时不必猜测。推断规则与 OWL API 一致，由 `owl-check` 验证。
  3. **平台的自动形状**（第 3.3 节）。
- **前缀**：依次是固定前缀、本体自己的前缀，以及导入时带来的、与前两者不冲突的前缀。本体自己的命名空间默认以本体标识为前缀名；由文件导入新建的本体沿用文件给这个命名空间起的名字（如 `ex:`）。一个命名空间一旦有了前缀名就不再改名，因为已保存的公理片段是用它书写的；之后再导入的文件换了名字也不影响。
- **确定性**：空白节点内联书写，RDF 列表用 `( … )`，独立的空白节点结构写成 `[ … ] .`。主语按 IRI 排序，公理按规范文本排序。同一状态两次导出，结果逐字节一致。
- **OWL 与 SHACL 放在同一个文件里**：实测 OWL API 4.5.29 读写 M1 的 v1 导出，没有丢失任何三元组，只补了声明（见第 4.3 节的实测记录）。

### 4.3 往返验收与 `owl-check`

**不丢内容**（pytest，纳入门禁）：用 21 个样例和钢铁样例的三份文件（`ontology.ttl`、`shapes.ttl`、`vocabulary.ttl`）逐个检查：

1. 导入后导出，原文件的每个三元组都出现在导出里。空白节点按同构比对，字面量按原写法比对。
2. 把导出再导入，与第一次导入相比差异为空；再导出的结果与第一次导出逐字节一致。
3. 钢铁样例另外用 pySHACL 校验：用导出的 SHACL 校验 `data.ttl` 应通过，校验 `invalid-data.ttl` 应不通过。

**Protégé 往返**（`./dev.ps1 owl-check`，不纳入门禁，在 PR 里贴结果）：

1. 在临时的 api 容器里，把每个样例导入平台再导出。
2. 在断网的临时 OWL API 容器里读入导出文件，另存为 Turtle，并记录解析错误和未解析的三元组。镜像是 `ontology/owlapi:local`，使用 OWL API 4.5.29，与 Protégé 5 同一系列。
3. 回到 api 容器，把另存的结果与第 1 步的状态比较。

判定标准：没有解析错误，没有未解析的三元组，差异为空；只允许 `non_standard` 公理被改写，已知样例 15、16、21 如此。

覆盖范围：21 个样例、钢铁样例，以及开发栈"钢铁冶金"当前版本的导出。OWL API 的 Maven 依赖经阿里云 Maven 镜像下载，只放进开发工具镜像，不进运行镜像。

**实测记录**（2026-11-23，用 OWL API 4.5.29 读写未经平台处理的原始文件）：

- 去掉 OWL API 补的声明、字面量按值比较之后，内容一致的有：M1 的 v1 导出、钢铁样例三份文件、21 个样例中的 18 个。
- 被改写的样例有三个：
  - 样例 15：基数用的是 `xsd:integer`，被读成错误类；
  - 样例 16 和 21：命名类直接带布尔构造，被改写为等价类。
- 字面量被改为规范写法，例如 `"01"` 变成 `"1"`、`"+02"` 变成 `"2"`。
- `sh:in` 后面的列表被丢掉，只剩一个空的 `sh:in [ ]`。原因是列表作为注解值不是 OWL 结构，OWL API 不保存它。平台的处理：
  - 读入时把 `sh:in [ ]` 记为"取值被 Protégé 丢掉"，照原样写回，不丢内容；
  - 导入到已有本体时，沿用平台里已有的取值；平台里也没有取值的，提示 `lost_list`。

**`owl-check` 结果**（2026-11-23，对平台导出的文件）：23 个案例全部通过。其中 20 个完全一致；样例 15、16、21 只有 `non_standard` 公理被改写；钢铁样例有 5 条规则的 `sh:in` 被 OWL API 丢掉，导回时保留了平台的取值；开发栈"钢铁冶金"v1 完全一致。

## 5 差异

`diff(当前状态, 目标状态)`：元素按 IRI 对齐（包括已删除的元素），公理按规范形式对齐。

| 情况 | 变更项 |
|---|---|
| 目标里有、当前没有的元素 | `create` |
| 两边都有、字段不同 | `update`，只包含变化的字段 |
| 当前有、目标里没有 | `delete` |
| 已删除的元素又出现在目标里 | `restore`，字段也有变化时一并修改 |
| 只在一边出现的公理或本体注解 | `create` 或 `delete`。公理没有 `update`，改写一条公理就是删一条、加一条 |

比较时，类型化字面量按值比较，空白节点按同构比较。

差异引擎用于四个地方：导入到已有本体、专家模式保存整份 Turtle、版本对比（第 9 节）、`owl-check`。

## 6 手工编辑（PR B）

**保存**：`POST /api/ontologies/{id}/edits`，请求体 `{ items, apply }`，每次保存生成一个"手工"变更集。

| 情况 | 结果 |
|---|---|
| 单人模式（默认）下，admin 或 reviewer 传 `apply: true` | 在同一事务里接受全部项并合并，返回合并结果。只要有一项会被跳过，就整体回滚，返回 409（`element.stale` 或对应的码），不留下半个变更集 |
| editor，或异人审核模式 | 变更集保持 open，进入审核页 |

**冲突**：修改、删除、恢复都必须带 `targetRevision`。与元素当前的 revision 不同时，返回 409 `element.stale`，界面提示"该元素已被修改，请刷新后再改"。

**删除与影响**：删除前先调用 `GET /api/ontologies/{id}/elements/{elementId}/impact` 计算影响。删除时，同一个变更集里一并带上级联项：
- 以它为定义域或值域的关系和属性：删除；
- 它的子类型：清空父类型；
- 以它为目标的约束：删除；
- 约束里引用它的规则：移除（规则移除光后约束保留，空规则列表合法）；
- 它的互逆关系：清空互逆；
- 提到它 IRI 的公理：删除。

级联项由服务端补齐，按传递闭包计算（被级联删除的元素继续向外级联），并以同一次保存里其他修改之后的引用为准：用户把引用改走的，不再清空或删除。某项仍引用、或要修改一个本次会被删除的元素时，整次保存返回 422 `changeset.invalid_edit`，不会只生效一半。影响分析接口返回完整的级联列表，确认框里列出全部级联项。

**表单**：

| 元素 | 字段 |
|---|---|
| 对象类型 | 中英文名、定义、同义词、父类型 |
| 关系 | 同上，另加定义域、值域、必填、允许多个、互逆 |
| 属性 | 同上，另加定义域、数据类型、单位、必填、允许多个 |
| 约束 | 目标类型、规则列表 |
| 公理 | Turtle 片段（第 7 节） |

新建元素的 `local_name` 由英文名生成建议值，用户可以修改，命名规则同 M1。

## 7 专家模式（PR B）

- **整份 Turtle**：本体页新增第三个视图"Turtle"。
  - 默认只读显示工作版本的导出，点"编辑"后可以修改。
  - "生成变更集"调用 `POST /api/ontologies/{id}/turtle`，处理方式与导入到已有本体相同。
  - 有语法错误时返回 422 `import.parse_error`，带行号和列号，不生成变更集。
  - 产生的变更集一律进审核页，不自动合并。
- **单条公理**：高级公理列表按主语分组，可以新建、修改、删除单条公理。编辑器会自动带上本体的前缀。保存规则与手工编辑相同（第 6 节）。片段要通过三项校验：
  - 能解析；
  - 恰好构成一条公理（第 3.4 节）；
  - 不是表单能表达的内容，否则返回 422 `axiom.maps_to_element`，提示到元素上编辑。这样可以保证导出再导入时不产生差异。
- **编辑器**：CodeMirror 6（MIT），使用 `@codemirror/legacy-modes` 的 turtle 模式。

## 8 审核模式（PR B）

配置项 `OP_REVIEW_MODE`，取值为 `single`（默认）或 `separate`。

- **separate 模式**：
  - 变更集的创建人（`created_by`）不能对它逐项决定或合并，返回 403 `changeset.self_review`；
  - AI 生成的变更集，创建人是发起上传或提问的人，同样适用。
- **撤回**：两种模式下，创建人都可以整体拒绝自己的变更集（撤回），包括没有审核权限的 editor；整体拒绝别人的变更集仍需要 reviewer。变更集接口返回 `createdBy`，审核页据此显示"撤回"和只读说明。
- **查询**：`GET /api/settings/platform` 返回 `{ reviewMode }`。设置页显示当前模式；编辑表单据此决定"保存"是直接生效，还是提交审核。

## 9 版本对比与影响分析（影响分析在 PR B，对比在 PR C）

**版本对比**：`GET /api/ontologies/{id}/compare?from=<releaseId>&to=<releaseId|working>`。结果按元素列出新增、删除和修改（含字段的前后值），以及公理的增删。每一项分为三级：

| 级别 | 情况 |
|---|---|
| 不兼容 `breaking` | 删除元素；改数据类型、单位、定义域、值域、父类型、互逆；必填由否改为是；允许多个由是改为否 |
| 需确认 `review` | 约束的新增、删除或规则变化；公理的增删 |
| 兼容 `compatible` | 新增元素；名称、定义、同义词的变化；必填由是改为否；允许多个由否改为是；恢复 |

**界面**：
- **版本页**：可以选两个版本对比，默认是当前版本对比工作版本。
- **发布对话框**：显示相对当前版本的变更摘要。有不兼容变更时显示黄色提示条："有 N 项不兼容变更，依赖这些元素的数据和查询可能失效"。

**影响分析**：`GET /api/ontologies/{id}/elements/{elementId}/impact`，返回子类型、相关的关系与属性、约束、公理和互逆关系。用在三个地方：元素详情侧栏的"被引用"区块、删除确认框、审核页修改和删除项的影响摘要。

## 10 AI 助手（PR C）

**面板**：快捷键 Ctrl/⌘ + J，包含：
- 输入框；
- 上下文：当前本体、所在页面、选中的元素；
- 本次会话的请求列表，以及每个请求的步骤进度；
- 回复与结果卡片：变更摘要和"去审核"；
- 失败提示和重试。

**接口**：

| 方法与路径 | 说明 | 角色 |
|---|---|---|
| `POST /api/ontologies/{id}/assistant/requests` | `{ message, context: { page, elementId? } }`，`message` 为 1–2,000 字；创建任务 `assistant.propose` | editor |
| `GET /api/assistant/requests/{id}` | 请求的状态与结果 | viewer |
| `GET /api/ontologies/{id}/assistant/requests?limit=20` | 当前用户最近的请求 | viewer |

**表 `ai.assistant_requests`**（迁移 v0006），列有：`id`、`ontology_id`、`user_id`、`message`、`context`、`status`（`queued` / `running` / `succeeded` / `failed`）、`step`（`context` / `model` / `changeset`）、`reply`、`change_set_id`、`error_code`、`created_at`、`finished_at`。

用户的原话和 AI 的简短回复属于用户自己的内容，保存下来以便在面板里回看。`ai.runs` 仍然不保存提示词。

**流水线**：
1. **context**：
   - 给模型本体的元素摘要：种类、名称、同义词、父类型、定义域、值域、数据类型、单位、必填、允许多个；约束和公理只给数量与主语。
   - 选中的元素给完整信息。
   - 元素超过 400 个时，只给与指令里的名称匹配的元素及其一跳邻居，并在提示词里说明。
2. **model**：使用 `OP_AI_MODEL`（日常模型，不触发 #9），结构化输出 `{ reply, operations: [{ op, kind, target?, tempRef?, fields, rationale, confidence }] }`。提示词要求：
   - 只做用户要求的修改；
   - 不确定时降低置信度；
   - 做不到时只在 `reply` 里说明原因。
3. **changeset**：由确定性代码校验每个操作，包括字段规则、引用和命名冲突；删除操作按第 6 节补上级联项。助手可以新建、修改、删除对象类型、关系、属性和高级公理；约束只能删除（规则结构复杂，在表单里编辑）。同一元素只取第一个通过校验的操作；依赖被丢弃项的操作一并丢弃。
   - 不合法的操作丢弃，数量记在请求的 `dropped` 里，面板在回复后附上"有 N 项无法执行，已忽略"。
   - 合法的操作生成来源为 `ai_assistant` 的变更集，标题为"助手：{指令前 60 字}"，所有项都是待审核。

**失败与超出范围**：
- 失败处理同 M1 网关（`ai.not_configured`、`ai.unavailable`、`ai.invalid_output`）。面板提示"AI 助手暂不可用，本体没有被修改"，可以重试。
- 超出范围的指令（问答、数据查询等）：回复"这类问题将在后续版本支持"，不生成变更集。

## 11 界面

遵守界面规范，每个数据区域都处理加载、空、出错、无权限四种状态，所有文字走 i18n。

- **本体页**：
  - 主按钮"新建"，可选对象类型、关系类型、属性或约束。
  - 视图有三种：图谱、列表、Turtle。列表的筛选增加"约束""高级公理"，默认不列出已删除的元素，可以筛选出来并恢复。
  - 元素详情侧栏增加"编辑""删除"、"被引用"区块，以及相关公理。
  - ⋯ 菜单里放"导入 OWL"和"导出 Turtle"。
- **新建本体弹窗**：可以选择"从 OWL 文件导入"。
- **审核页**：
  - 来源标签：资料识别、导入、手工、AI 助手；
  - 删除项和恢复项有专门的展示；公理项用等宽字体显示 Turtle，`non_standard` 带 ! 图标；约束项显示规则表；
  - "导入""手工"来源提供"接受全部"；修改项和删除项显示影响摘要。
  - 证据入口和证据面板只在 AI 来源（资料识别、AI 助手）的变更集里出现；导入和手工修改没有资料原文，不显示。
- **导入结果**：会影响结果的警告用黄色提示条（界面规范第 4 节），即 `kind_changed`（换了种类的元素保持原样，指向它们的引用没有导入）和 `lost_list`（枚举取值丢失且平台里没有可沿用的值）；只是写法不同、内容原样保留的警告（`non_standard`、`multiple_parents`、`unsupported_shape`）用 ! 图标。
- **本体为空**：主按钮"上传资料"（AI 识别），次要按钮"导入 OWL 文件"，两种起步方式（界面规范第 5 节）。
- **版本页**：增加对比视图；发布对话框显示变更摘要和不兼容提示条。
- **AI 助手面板**：见第 10 节。助手生成的变更项带 ✦ AI 建议标识和置信度。
- **设置页**：显示审核模式。

## 12 测试

**后端：**
- **映射与导出**：
  - 第 4.3 节的往返测试；
  - 每条映射规则；派生三元组的吸收；字面量写法的保留；
  - 输出逐字节稳定（黄金文件）；公理的拆分与共享空白节点；`non_standard` 的判定；
  - 导入限制：格式、大小、三元组数、语法错误的行号；不联网（`owl:imports` 不加载）。
- **差异**：每种变更；字面量按值比较；同构的空白节点不算变化；恢复。
- **合并**：删除与恢复；级联；`changeset.has_dependents`；公理项和约束项；互逆。
- **手工编辑**：自审合并；冲突返回 409；各接口的角色检查；两种审核模式。
- **助手**：用假网关覆盖生成变更集、丢弃不合法的操作、只回复不生成、失败提示。
- **迁移**：在有 M1 数据的库上升级后，M1 的接口测试照常通过。

**前端**：导入、编辑表单、删除确认与影响、专家模式、版本对比、助手面板，都要有主要交互的测试。
